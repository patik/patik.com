# Photo Gallery System

This directory contains the utilities that power the Cloudinary-backed travel photo galleries.

## How photos are organized

### On Cloudinary

For new galleries, photos should live in folders named `{Year} {Country}/{City}`. Some existing folders use a legacy country-first pattern, e.g. `Uzbekistan 2023/Samarkand`.

```
2017 Vietnam/Hanoi
2017 Vietnam/Ha Long Bay
2018 Italy/Florence
Uzbekistan 2023/Samarkand
```

Spaces in folder names must be escaped with a backslash **in TypeScript strings only** (this is a Cloudinary search API requirement — it is NOT a filesystem path):

```ts
cloudinaryFolder: '2017\\ Vietnam/Ha\\ Long\\ Bay'
```

At build time, `fetchFolderFromAssetProvider` queries the Cloudinary search API using `folder:{folderName}/*` and caches the JSON response to `tmp/cloudinary-cache-{key}` so subsequent builds don't re-fetch. Delete files in `tmp/` to force a re-fetch.

### In this repository

Three layers of files implement a country's gallery:

```
src/
├── galleries/
│   └── {country}/
│       ├── index.ts          ← CountryGallery (preferably also exports cityGalleries array)
│       ├── {city}.ts         ← CityGallery (one file per city)
│       └── ...
├── images/
│   └── {country}-{city}-{description}.jpg   ← hero image for the TravelLinkList card
└── pages/
    └── travel/
        └── {country}/
            ├── index.astro                   ← country landing page
            └── photos/
                └── [...photos].astro         ← all gallery/lightbox routes
```

## Types (`src/photos/utils/types.ts`)

| Type | Key fields | Used for |
|---|---|---|
| `CountryGallery` | `countryId`, `countryName`, `cloudinaryFolder`, `title`, `keywords` | Country-level gallery config |
| `CityGallery` | extends `CountryGallery` + `cityId` | Per-city gallery config |
| `CloundinaryResource` | `public_id`, `secure_url`, `width`, `height`, `format`, `resource_type` | Raw API response from Cloudinary |
| `ImageProps` | `id`, `public_id`, `secure_url`, `width`, `height`, `format`, `resource_type` | Normalised image used throughout the UI |

> Note: `CloundinaryResource` has a deliberate typo that matches the existing codebase — do not rename it.

## Utilities (`src/photos/utils/`)

| File | Purpose |
|---|---|
| `cloudinary.ts` | Configures the Cloudinary SDK from env vars (`PUBLIC_CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`) |
| `fetchFolderFromAssetProvider.ts` | Fetches all resources in a Cloudinary folder, with filesystem caching to `tmp/` |
| `getImageUrl.ts` | Builds a Cloudinary delivery URL with `c_scale`, `f_auto`, `q_auto:good` transforms |
| `getImageUrlToBeBlurred.ts` | Returns a tiny low-quality variant for blur-up placeholders |
| `escapeCloudinaryString.ts` | Escapes special characters in `public_id` strings for use in Cloudinary URLs |

## UI components

| Component | Purpose |
|---|---|
| `src/components/gallery/PhotoGrid.astro` | Renders a masonry/grid of thumbnails; each links to its lightbox route |
| `src/components/gallery/PhotoLightbox.astro` | Full-screen lightbox for a single photo with prev/next navigation |
| `src/components/TravelLinkList.tsx` | Card grid on country landing pages; each card shows a hero image and links to a city gallery |

## Routes generated by `[...photos].astro`

The catch-all segment `[...photos]` covers four route shapes:

| URL | `photos` param | What renders |
|---|---|---|
| `/travel/{country}/photos/` | `undefined` | `PhotoGrid` with all country images |
| `/travel/{country}/photos/42` | `"42"` | `PhotoLightbox` for image 42 (country level) |
| `/travel/{country}/photos/{city}/` | `"{city}"` | `PhotoGrid` with city images only |
| `/travel/{country}/photos/{city}/7` | `"{city}/7"` | `PhotoLightbox` for image 7 in that city |

`getStaticPaths()` pre-generates every path at build time. If Cloudinary credentials are absent, `fetchFolderFromAssetProvider` returns `{ resources: [] }` and the gallery pages build with zero images (safe for local development without credentials).

## Adding a new country

1. **Create gallery configs** — `src/galleries/{country}/index.ts` (exports `default`; prefer exporting named `cityGalleries` for reuse in `[...photos].astro`) and one `{city}.ts` per city.
2. **Add hero images** — one JPEG per city at `src/images/{country}-{city}-{description}.jpg` (800×600 or larger).
3. **Create the country page** — `src/pages/travel/{country}/index.astro` using `TravelLinkList`.
4. **Create the dynamic gallery page** — `src/pages/travel/{country}/photos/[...photos].astro`; copy the Italy or Vietnam version and swap the imports/country slug.
5. **Update `src/countries.json`** — add the country to the `visited` array with `name` and `yearsVisited`.
6. **Update `src/pages/travel.astro`** — add a TravelLinkList card so the new trip appears on the main Travel page.

### Cloudinary folder naming rules

- Preferred folder format on Cloudinary for new galleries: `{Year} {Country}/{City}` using natural spaces (e.g. `2017 Vietnam/Ha Long Bay`)
- Legacy folders may use `{Country} {Year}/{City}` (e.g. `Uzbekistan 2023/Samarkand`)
- In TypeScript `cloudinaryFolder` strings, escape every space with `\\ ` (double backslash because it's inside a JS string, producing a single `\` at runtime)
- City IDs (`cityId`) use lowercase kebab-case matching the URL segment (e.g. `ha-long-bay`)

## Test snapshots

When a new country is added to the travel index page, the snapshot for that page will need to be updated:

```sh
pnpm build && pnpm playwright test visual --update-snapshots --grep "travel-index"
```

Also run `.github/workflows/update-snapshots.yml` once pushed to regenerate the CI's snapshots.
